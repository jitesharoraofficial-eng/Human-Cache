## 2. Root Cause Analysis & Fixes

### A. Database Test Fixture Isolation (Fixing 4 Failing Tests)
* **Root Cause Identified:** In `tests/test_simplified_connectivity_and_part5.py` and `tests/test_coverage_and_adaptive_flashcards.py`, test routines directly invoked `SessionLocal()` (pointing to the live `human_cache.db`) while `test_auth_and_isolation.py` had registered FastAPI dependency overrides pointing to `TestingSessionLocal()` (`test_human_cache.db`). When run sequentially, test seeds went to the primary SQLite database while endpoint handlers queried the isolated test database, resulting in HTTP 404s and assert failures.
* **Resolution:** Re-routed all test files to consistently import `client` and `TestingSessionLocal` from `tests.test_auth_and_isolation`. Tests run in complete isolation with transactions cleanly rolled back and closed. Never writes to live user data.

### B. Notification Pop-up Delivery & Four-Way Action Lifecycle
* **Root Cause Identified:** The database model `Notification` defaults `action_state="active"`, but the frontend filter in `frontend/src/app/page.tsx` was looking strictly for `action_state === "pending"`. Consequently, active unread review alerts generated by the memory coach never surfaced as toast pop-ups.
* **Resolution:**
  1. Updated `backend/schemas.py` (`NotificationResponse`) with `action_state: Optional[str] = "active"`.
  2. Updated `frontend/src/app/page.tsx` to accept notifications where `(!n.action_state || n.action_state === "active" || n.action_state === "pending")`.
  3. Implemented priority-based toast queuing: `urgent` (4) > `high` (3) > `normal` (2) > `low` (1).
  4. Added `sessionStorage` tracking (`humancache_dismissed_toast_ids`) in toast close and action callbacks to prevent repetitive pop-ups across tab refreshes during an active study session.
  5. Harmonized the contract for all four actions (**Start**, **Dismiss**, **Remind Me Later / Snooze**, **No Need**):
     - `POST /notifications/{id}/start` returns navigation payload with `action_state="started"`.
     - `POST /notifications/{id}/dismiss` returns `action_state="dismissed"`.
     - `POST /notifications/{id}/snooze` accepts both JSON payload and query parameters (`minutes` / `snooze_minutes`), returns `is_snoozed=True`, `action_state="snoozed"`.
     - `POST /notifications/{id}/no-need` permanently mutes reminders for the specific concept in `TopicMemoryState`, suppresses toasts, and allows re-enabling anytime in Settings.
  6. Added 9 regression tests in `tests/test_notifications.py` verifying the full state lifecycle.

### C. Secure Upload Handling & Magic Byte Validation
* **Root Cause Identified:** `/documents/upload`, `/capture/file`, and `/exams/date-sheet/extract` previously called `file.file.read()`, buffering entire multi-megabyte payloads into RAM before verifying file size, and relied solely on file extensions. This allowed disguised executables (PE/ELF) and risked out-of-memory denial-of-service on large payloads.
* **Resolution:**
  1. Created `backend/file_security.py` with `stream_save_and_validate(...)`.
  2. Enforces `settings.MAX_UPLOAD_SIZE_MB` (25 MB) by streaming directly to disk in 64 KB chunks without loading the entire payload into RAM.
  3. Aborts and immediately removes partial files from disk if the cumulative stream exceeds 25 MB or is 0 bytes.
  4. Magic-byte inspection on initial chunk rejects:
     - Windows PE binaries (`MZ`)
     - Linux ELF binaries (`\x7fELF`)
     - Java/Mach-O universal binaries (`\xca\xfe\xba\xbe`, `\xfe\xed\xfa\xce`)
     - Extension mismatches for PDF (`%PDF-`), DOCX (`PK\x03\x04`), PNG (`\x89PNG\r\n\x1a\n`), JPEG (`\xff\xd8\xff`), and WEBP (`RIFF....WEBP`).
     - Text files containing binary null bytes (`\x00`).
  5. Structural validation for PDFs: calls `pypdf.PdfReader` to detect unparseable/corrupted PDFs before database commit.
  6. Added regression tests in `tests/test_upload_safety.py` confirming rejection of >25MB files, malicious binaries, and malformed PDFs.

### D. PDF Performance Instrumentation
* **Resolution:** Granularly decomposed the ingestion pipeline in `backend/extractor.py` and `backend/main.py`:
  - `upload_save_ms`: Streaming disk write & magic-byte validation
  - `text_extraction_ms`: `extract_raw_pages_and_text`
  - `chunking_ms`: `chunk_pages_and_text`
  - `db_chunks_ms`: Database insert of `SourceChunk` records and commit
  - `vector_embedding_ms`: Vector embedding computation & indexing
  - `graph_extraction_ms`: Concept node and relationship extraction
  - `db_graph_ms`: Topic, TopicMemoryState, and TopicRelationship commit
  - `total_duration_ms`: Total end-to-end request turnaround
* **Structured Performance Logging:** Logs JSON operational telemetry (`logger.info("PDF_PERF_METRICS: %s", ...)`) containing document ID, file type, file size, page count, chunk count, and sub-second timing breakdown.
* **Document Confidentiality:** Zero document text, snippets, or private excerpts are recorded in logs or performance telemetry.

### E. Browser Extension Reliability
* **Resolution:**
  1. Updated `extension/manifest.json`: added required `"notifications"` permission and allowed HTTPS host permissions (`https://*/*`) alongside localhost defaults.
  2. Updated `extension/background.js` and `extension/popup.js` to dynamically load `humancache_api_url` from `chrome.storage.local` with fallback to `http://127.0.0.1:8000/api/v1`.
  3. Added settings toggle in `extension/popup.html` allowing users/testers to easily point the extension to custom backend ports or remote tunnel URLs.
  4. Added `try/catch` and fallback notification around `chrome.action.openPopup` to prevent unhandled promise rejections in Chromium service workers.
  5. Verified CORS configuration in `backend/main.py` (`allow_origin_regex=r"^(chrome-extension|moz-extension|edge-extension)://.*$"`).
  6. Added automated manifest validation tests in `tests/test_extension_manifest.py`.

### F. Frontend Offline Build Resilience
* **Resolution:** `frontend/src/app/layout.tsx` was attempting to fetch `Geist` fonts from `fonts.googleapis.com` at build time, failing when building in offline/proxy environments. Replaced with system font stack configured in `globals.css` (`system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`). `next build` now compiles cleanly offline in 6.3s.

## 5. Comprehensive Manual Verification Checklist

The following test checklist outlines specific manual verification steps required in physical browsers and mobile devices:

### A. In-App Notification Toast & 4-Way Action Lifecycle
- [ ] **Trigger:** Log in to `http://localhost:3000`. Navigate to Exam Planner and schedule an exam 2 days in the future to trigger an exam reminder.
- [ ] **Pop-up Appearance:** Within 30 seconds (or on initial load), verify the bottom-right toast appears with the correct priority badge (`Priority` for exams, `AI Memory Coach` for standard drills).
- [ ] **Action A (Start):** Click "Start Drill". Confirm that navigation redirects to the appropriate view (`/exam` or `/recall`) and the toast immediately dismisses.
- [ ] **Action B (Dismiss):** Re-trigger or let a notification appear. Click the "X" button. Confirm toast disappears and does not reappear during the active session.
- [ ] **Action C (Remind Me Later):** Click the dropdown arrow on the toast and select "1 Hour" or "30 Mins". Confirm toast disappears and endpoint `/snooze` sets `snooze_until`.
- [ ] **Action D (No Need):** Click "No Need". Confirm browser prompt warns about permanently muting the concept. Upon confirmation, verify the concept reminder is suppressed and visible under Settings > Suppressed Concepts.

### B. Chrome/Edge Extension Capture
- [ ] **Extension Loading:** Open `chrome://extensions`, enable Developer Mode, click "Load unpacked", and select `Human Cache Demo/extension`.
- [ ] **Connection Indicator:** Click the extension icon. Verify green dot indicating "Connected as <email>" (or login form if logged out).
- [ ] **Settings Configuration:** Click the ⚙️ icon in popup. Verify the backend URL defaults to `http://127.0.0.1:8000` and can be changed.
- [ ] **Page Capture:** Navigate to any article (e.g. Wikipedia). Open extension popup and click "⚡ Save Page to Human Cache". Verify success alert and desktop notification.
- [ ] **Context Menu Capture:** Highlight a paragraph on any webpage, right-click, and select "Save to Human Cache". Verify Chrome notification appears indicating item was saved to Capture Inbox.
- [ ] **Capture Inbox Review:** Open Web App > Capture Inbox. Verify captured text excerpt and suggested category appear with options to confirm or discard.

### C. PWA Share Target & Mobile Responsiveness
- [ ] **PWA Installability:** Open Chrome on Android or desktop, verify the "Install Human Cache" prompt is available.
- [ ] **Incoming Share Target:** Using Android share menu from another app (e.g. Chrome browser or Twitter/X), select "Human Cache". Verify the app opens and automatically displays the Smart Capture modal with title, URL, and text populated.
- [ ] **Outgoing Share:** On any completed note, mind map, or quiz result, click "Share" and verify Web Share API opens the native OS share sheet (with fallback to copy link on unsupported desktop browsers).
